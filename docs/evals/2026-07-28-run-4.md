## Findings

1. **A worktree has no `vendor/`, so builders cannot verify anything.** The
   `tests` case says it outright: qa-engineer *"wrote suite in worktree
   (couldn't run — no vendor/)"*, and the main thread then installed
   dependencies and re-ran the suite itself, fixing two of qa's tests. `git
   worktree add` checks out **tracked** files only — `vendor/`,
   `node_modules/` and `.env` are gitignored, so `isolation: worktree` lands
   every builder in a directory where no gate can run. Three consequences,
   all observed: work ships unverified, the main thread duplicates the
   verification, and `composer install` appears as an explicit stage in both
   the `action` and `policy` boards. This is not a fixture artifact — real
   projects gitignore `vendor/` too. Under Sail it is worse than useless: the
   container mounts the main project directory, so a worktree-resident agent
   either boots a second colliding container stack or tests the wrong tree.

2. **The NOT-CHECKED contract never reaches the user.** `tests` failed the
   `NOT-CHECKED` check, and the cause is structural: nine of ten commands say
   *"Demand each specialist return `STATUS / DID / VERIFIED / NOT-CHECKED /
   FLAGS / NEXT`"* — a contract on **specialist→coordinator** returns, which
   are internal. Headless `-p` prints only the final assistant message.
   `/team-hygiene` is the sole command that asks the runner itself to report in
   that shape. The honest content was present as prose in every case
   ("PHPStan not run — no `phpstan.neon` exists", "its work was unverified"),
   just never labelled. The check was right; the pack was wrong.

3. **qa-engineer pinned a live IDOR as expected behavior.** `tests` failed the
   `assertForbidden|403` check. Dina *found* the unguarded `update` route and
   flagged it in prose — then wrote a test asserting *"non-owner update pinned
   as current behavior"*. The always-check rule
   (`qa-engineer.md:99`) fires only for endpoints that are **already**
   protected, so an unprotected one gets characterized instead of probed. Net
   effect: a vulnerability became a passing test that a future fix will
   "break".

4. **qa-engineer is the wall-clock bottleneck in every multi-stage case** —
   634s (`policy`), 501s / 110k tokens (`action`): 60%+ of stage time. Run 3's
   scope-rule win (448s → 130s) did not hold. The `policy` case shows where it
   goes: Dina wrote allowed+denied pairs for **all seven** Policy methods, and
   its own report admits `delete`/`restore`/`forceDelete` *"have no
   corresponding routes"*. It spent minutes testing abilities the application
   cannot reach.

5. **`SubagentStop` carries no `duration` in practice.** Every
   `subagent_stop` event in all five feeds has `ms: null`. The emitter reads
   `.duration` (documented as a seconds float); real payloads don't include
   it. Lane *closing* works, and `board.html` already fell back to the
   `start`→`stop` timestamp delta, so the dashboard was never wrong — but the
   **feed itself** was un-timed, which is why this document's `policy` stage
   numbers had to be subtracted by hand and why the harness's copied feed
   carries no durations. The guardrails test passed only because it fed a
   synthetic `duration`. **Fixed in v1.25.0:** the emitter derives `ms` from
   the matching start event when `duration` is absent (pairing by
   `sid` + `agent` + latest start), the dedupe key normalises `ms` so the
   concurrent twin still collapses, and an unpaired stop is left `null` rather
   than guessed. Three tests cover it, including an exact-elapsed assertion.

6. **Honesty discipline is holding.** Unprompted and correct across cases:
   the mass-assignment hole was closed again in both write cases, `policy`
   surfaced seven pre-existing issues including a real `APP_KEY` in
   `.env.example`, and `action` refused to claim a PHPStan pass with no
   `phpstan.neon` present. The gap in finding 2 is formatting, not character.

## Acted on in v1.24.0

Findings 1–4 are the whole tranche; the answer key needed no change, since
fixes 2 and 3 make both failing checks legitimately passable.

- **1** → `isolation: worktree` removed from all eight writers; the rule in
  `docs/authoring-agents.md` inverts, and builders gain an explicit file-scope
  principle in place of the isolation guarantee.
- **2** → the shared `Interface` block now requires the run's **own final
  answer** to close with `VERIFIED` + `NOT-CHECKED`.
- **3** → qa-engineer must assert the *secure* expectation on an unprotected
  endpoint, mark it todo/incomplete, and flag it — never pin the hole.
- **4** → the scope rule gains a checkable edge: cover abilities with a real
  call site; unreachable ones go to NEXT.
