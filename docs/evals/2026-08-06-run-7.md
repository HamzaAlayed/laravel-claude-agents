## Findings

### 1. The `teach` judge disagreement is a fixture artifact, not a real failure

`teach` scored 6/6 on the regex key. The judge scored it 1/5, disagreeing,
citing "git status/diff show zero changes, contradicting the transcript's
claim." Both cannot be right — investigated directly:

- The kept workdir's `docs/team/conventions.md` exists, is 687 bytes, and
  contains the exact taught rule in full Rule/Why/Scope/Source shape.
- `git status` in that workdir reports "nothing to commit, working tree
  clean" — but `git check-ignore -v docs/team/conventions.md` shows why:
  the fixture app's own `.gitignore` has a top-level `/docs` entry, written
  long before `/teach` existed, that blanket-hides the entire `docs/` tree
  from git. The judge's git-based verification heuristic was fooled by the
  fixture, not by the run.

**Verdict: the regex check was right, the judge was wrong.** No fix needed —
this is exactly the audit doc's stated trust ordering (artifact checks over
the advisory judge) working as designed, empirically confirmed rather than
just asserted. Not a fixture bug worth changing either: the `/docs` ignore
predates this feature and nothing about `/teach`'s contract depends on the
ledger being tracked by git.

### 2. Harvest fails because `/make-feature` never loads the file that promises it — this run repeats a diagnosis run 6 already made

**Corrected after the final whole-branch review.** This finding's first
draft blamed a headless-turn-ending gap in `agents/delivery-coordinator.md`.
That diagnosis was wrong, and the branch had the evidence to catch it
before spending anything on a fix: `teach-delivery`'s prompt is
`/make-feature Donation --api` — a **command**, run on the main thread.
`commands/make-feature.md` never mentions `docs/team/stack.md` or
`docs/delivery/`, and never spawns a `delivery-coordinator` subagent. Both
this run's and the re-run's `teach-delivery.cost.json` attribute every turn
to `backend-developer`, `database-developer`, `main`, `qa-engineer`, and
`tech-lead` — never `delivery-coordinator`. The harvest steps this finding
originally cited (`agents/delivery-coordinator.md:104` for the stack
snapshot, `:113` for the delivery log) live in a file this invocation never
reads.

**This is not a new discovery — it is [run 6](2026-08-04-run-6.md)'s
finding 6 recurring, unrecognized:**

> "the tranche's rule lived only in `agents/delivery-coordinator.md`, and
> `/make-feature` is driven by the main thread — `delivery-coordinator` is
> never spawned... A rule written into an agent body cannot govern work the
> main thread does inline through a command."

Run 6 hit exactly this gap for the stage-budget rule, and the fix that
worked was **moving the rule into the shared `Interface` block** all 9
pipeline commands carry (v1.24.0, then v1.36.0) — not editing the agent
body. The same pattern applies here: harvest needs to be promised somewhere
`/make-feature` (and the other 8 commands) actually load, or the command
needs to invoke the coordinator agent itself. Neither happened in this
release; see the addendum for what was attempted instead, and the
follow-ups for the scoped fix this defers to 1.41.

The checks themselves are not at fault: `check_file "docs/team/stack.md"`
and `check_file_under "docs/delivery" "log.md"` are both correctly
artifact-based, and both correctly failed on an artifact that genuinely
does not exist. Confirmed via `find` and `git status --short` in the kept
workdir, not taken on the check's word — the check's *verdict* was right
throughout; only this finding's *explanation* of the verdict was wrong at
first.

### 3. The "board declares a completion condition" check verifies the wrong slice of the transcript — both of its failures today are false negatives

`teach-delivery` and `feature` both failed `check_log 'done when:'
"board declares a completion condition"`. Both judges disagreed with the
regex verdict. Investigated directly, past what either the check or the
judge could see:

- `$LOG` (what the check greps) is rebuilt by `scripts/eval-cost.py
  --text-only` from the CLI's `result` line — the **final** text of the
  whole `-p` invocation only. It was built this way deliberately (the
  stream is JSON and would false-match tool inputs/thinking text if grepped
  directly) but as a side effect it can never see an **earlier** turn.
- The Interface (`commands/make-feature.md:11`, byte-identical across all 9
  pipeline commands since v1.36.0) mandates the `N stages · done when: ...`
  phrase in the **board header**, printed **before any agent spends
  tokens** — i.e. early, not in the closing summary.
- Claude Code itself persists the full session transcript independently of
  the eval harness's own kept artifacts, at
  `~/.claude/projects/<workdir-path-hash>/*.jsonl`. Reading those directly
  (not `$LOG`, not the harness's `agent-events.jsonl`) shows **both runs
  printed the phrase correctly, early, exactly as specified**:
  - `feature`: `"## Plan\n\n**4 stages · done when:** Tag API resource
    (migration + model + factory → Form Requests + Resource + P[olicy]..."`
  - `teach-delivery`: `"**4 stages · done when:** migration+model+factory
    exist, Form Request+Resource+Policy+Controller+route..."`

**Verdict: v1.36.0's fix works. The pack complies with its own Interface.
The check regressed, not the product.** This is a *new* regression in test
methodology (a check built for the previous shape of the harness's kept
artifacts, now stale against what `$LOG` actually contains) — not a
re-argument of run 6's original stage-budget-placement finding, which
run-7-scope named out of scope. See Task 7 for the fix (persist full
assistant text, not just the closing result, for this specific check to
read); it needs no new billed run to validate, since the transcripts already
captured above are sufficient evidence.

Net effect on `feature`'s score: its true result is **6/6**, not 5/6 — the
only "failure" was this check. `teach-delivery`'s true obedience/board
result is undiminished by this bug; its harvest failure (finding 2) stands
on its own, independently confirmed via the filesystem, not this check.

## Addendum: a fix was attempted before the scoping gap was found, and re-run

**This section originally reported "the fix works as designed, and the
re-run proves it." That claim did not survive the final whole-branch
review and has been withdrawn — kept here, corrected, because the sequence
of getting it wrong is itself worth recording.**

Before finding 2 was corrected (above), it was diagnosed as a headless
turn-ending gap in `agents/delivery-coordinator.md`, and human-approved
(case: `teach-delivery`, reason: validate the fix, price: ~$5) to fix and
re-run on that basis. The fix landed: the coordinator's "Parallel vs
sequential" section now requires parallel lanes to be awaited together,
never narrated as backgrounded with "I'll follow up." **But `/make-feature`
never loads that file**, so the edit could not have changed anything about
this specific run, in either direction.

The re-run's own numbers: **6/8 checks, judge FAIL 2/5** (a reversal from
the original run's judge PASS 5/5 — the judge changed its mind between the
two runs, on a prompt and ledger that didn't change), **1204s, $4.49**, and
it **timed out** (`EVAL_TIMEOUT=1200s`). Confirmed in the kept workdir: no
`docs/team/stack.md`, no `docs/delivery/**/log.md`, same as the original
run. The re-run's transcript has no "I'll follow up" framing and shows the
main thread waiting on `qa-engineer`/`tech-lead` rather than declaring them
backgrounded — but since the edited file was never in context for this
invocation, the more likely explanation is ordinary run-to-run variance
(`backend-developer` alone took 773s here against 152s originally, on an
unchanged prompt and an unchanged agent body), not the fix. `done when:`
was found via `check_log_anywhere`, but inconclusively as a check on
finding 3's fix specifically: a timed-out run never emits a `result` line,
so `$LOG` falls back to concatenating assistant text too (deliberately
unfiltered by agent, unlike `$FULL_LOG` — see `full_text()`'s docstring)
— and the two files happen to be byte-identical for this run, because
`qa-engineer`/`tech-lead` started but never returned any text before the
timeout killed the process. That is a fact about this run's shape, not a
general guarantee the two files agree on a timeout — a run where a
subagent's text lands before the kill would see them diverge. Either way,
this run cannot distinguish the old check from the new one. Finding 3's
reconstructed-transcript dry validation remains the clean proof of that fix.

**Net: the coordinator edit is real, defensible guidance for actual
`claude --agent delivery-coordinator` sessions — and unvalidated by
anything in this run, because the run never exercises that agent.** It
ships in 1.40 on its own merits, not as a validated fix for finding 2.
Finding 2's actual fix — moving the harvest requirement to where
`/make-feature` and its 8 sibling commands can see it, per run 6's own
precedent — is scoped as a 1.41 follow-up below, not attempted here: it
touches all 9 command Interface blocks, needs its own re-run to validate,
and the remaining budget (~$9.69 after this re-run) does not comfortably
cover a fix of that size plus validation.

**Spend:** re-run cost $4.49 (projected ~$5, spent on validating a fix that
turned out not to apply here — an honest cost of the mis-diagnosis, not of
the milestone's actual scope). **Milestone total: $20.31 of the $30
ceiling** ($15.82 original run + $4.49 this re-run).
