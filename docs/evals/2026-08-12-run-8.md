# Eval run 8 — a new check's own bug, and what the failure actually revealed — 2026-08-12

**Trigger:** the agent-orchestration-audit plan (`docs/superpowers/plans/2026-08-12-agent-orchestration-audit.md`, Task 5) added a new assertion to the opt-in `feature` case: that a delegated run's per-stage returns carry the full `STATUS/DID/VERIFIED/NOT-CHECKED/FLAGS/NEXT` shape the shared Interface block mandates. A billed run ($3.44, 726s, run id `20260812T172051Z`) scored it 8/9 — the new check failed.

**What it looked like at first:** `STATUS:`, `DID:`, `FLAGS:`, `NEXT:` never appeared anywhere in `$FULL_LOG` (0 occurrences each); `VERIFIED:`/`NOT-CHECKED:` appeared once each. Read at face value, this looked like a real coordinator defect — the Interface block's per-stage contract silently not followed, even though delegation (4 distinct agents, confirmed via `check_delegated`) and harvest (`docs/team/stack.md` + a delivery log, both confirmed present) both worked.

**What it actually was:** the check greps `scripts/eval-cost.py`'s `full_text()` output, which deliberately filters to main-thread turns only — the same guard `check_log_anywhere`'s own precedent (run 7, finding 3) relies on to stop a specialist's own text from satisfying a contract that only binds the orchestrator. A per-stage return is, by definition, a subagent turn. `STATUS:`/`DID:`/`FLAGS:`/`NEXT:` can never appear in this stream regardless of how faithfully the coordinator complies — the check was asserting on a log that structurally cannot contain its own subject. The single `VERIFIED:`/`NOT-CHECKED:` hit is exactly the main-thread's own closing-answer contract (the Interface block's last sentence: "Your own final answer closes the same way"), which is the only part of the six-field shape this stream can ever see.

**The fix:** `checks_feature()`'s new assertion was narrowed to what `$FULL_LOG` can actually verify — the coordinator's own closing `VERIFIED`/`NOT-CHECKED` lines (two `check_log` calls, matching the same idiom `checks_tests()` already uses for `NOT-CHECKED`) — and the custom `check_stage_return_shape` function was removed. Both narrowed checks pass against this same run's artifacts already on disk; no new billed run was needed.

**What this leaves open:** whether specialists' own per-stage returns actually carry the full contract shape is still unmeasured — `eval-cost.py` has no derived log that includes subagent text, and `tests/guardrails.test.sh` forbids any `checks_*` function from reading the raw `stream.jsonl` transcript directly. Proving per-stage compliance would need a new subagent-inclusive extraction mode added deliberately (not a `checks_*` workaround) — real work, and its own plan, not a one-line fix. Filed as a gap, not a coordinator defect: nothing here suggests the coordinator or specialists are non-compliant, only that this harness cannot currently observe the per-stage half of the contract.

**Cost:** $3.44, 726s, run id `20260812T172051Z` (artifacts are local-only and gitignored — this write-up is the durable record).
