Its `feature.cost.json` billed `$6.548779…` with `rate_table_check.agrees: true`.

Run 9 verified real HTTP and re-briefed.

### 2. Wall clock inside `max_seconds` (1900) while hitting `EVAL_TIMEOUT` (1200) is a harness split the seed already required — teach-delivery already named it

`tests/eval/run-evals.sh` line 50: `EVAL_TIMEOUT="${EVAL_TIMEOUT:-1200}"`. The comment on line 26 has said `EVAL_TIMEOUT=1200` since the harness landed (`ae2d946`, 2026-07-20). `git log -S 'EVAL_TIMEOUT="${EVAL_TIMEOUT:-1800}"'` is empty — the default was never 1800. Soft ceilings live in `baseline.json` and "Warns, never fails" (`run-evals.sh` lines 789–835). The hard kill is `run_with_timeout "$EVAL_TIMEOUT"` (line 686). Timeout is printed when `$dur -ge $EVAL_TIMEOUT` (line 725); scoring still runs.

**The seed cannot complete under the default kill.** `20260804T202949Z/feature.stream.jsonl` has a `type: result` line, `subtype: success`, `duration_ms: 1454413` (1454s), `total_cost_usd: 6.548779…`. A 1456s success is 256s past 1200. That run was therefore invoked with `EVAL_TIMEOUT` raised above 1456s. The same day's five-case sweep is documented as `EVAL_TIMEOUT=1800` ([run 6](2026-08-04-run-6.md) opening line).

**`max_seconds` 1900 is +30% of 1456, uncapped.** `1456 * 1.3 ≈ 1893`, stored as 1900 (`baseline.json` `cases.feature.basis`). `teach-delivery` already refused that arithmetic: its `basis` says 939s + ~30% "would land at 1220s, past the harness's own hard kill, which cannot be a valid ceiling since no run can ever measure above 1200s without timing out first" — so that case is capped at 1150s. `feature` was seeded the same week *without* applying that cap. A run that looks like the seed (1456s) is structurally a timeout under default `EVAL_TIMEOUT`, and a `within 1900s` print on a 1203s kill is the split doing what the numbers say, not a new 1.42 bug.

**Run 9's 1203s is the watchdog, not the work finishing.** [Run 9](2026-08-18-run-9.md): harness printed `TIMED OUT after 1203s` then still scored. `$FULL_LOG` ends mid-board at `Wai`. A 30s TERM grace is in `run_with_timeout` (`run-evals.sh` lines 532–535), which is why the printed duration is 1203 rather than 1200.

### 3. The 1.42 Interface clause caused the expensive path on this fixture. A pre-1.42 orchestrator on the same prompt patched or stopped; it did not loop

v1.42.0 appended two sentences to the shared Interface block (all 9 pipeline commands; `commands/make-feature.md` line 11):

> **You do not build and you do not patch** — Write/Edit only under `docs/**`; never edit a specialist's files to "just fix it" (re-brief or escalate). **Verify before advancing** — re-run that brief's success criteria yourself; a specialist's `STATUS: done` is a claim, not a `✔`.

Those two sentences are exactly the audit's Blocking findings ([orchestration audit](2026-08-12-orchestration-audit.md) Dimension 1): write-scope / never-patch, and verify-before-advancing, had lived only in `agents/delivery-coordinator.md`, which a command-driven `/make-feature` never loads ([run 6](2026-08-04-run-6.md) finding 6; [run 7](2026-08-06-run-7.md) finding 2).

**Run 9 followed both clauses, visibly.** [Run 9](2026-08-18-run-9.md): no main-thread `Edit`; `✔ a` annotated "I re-ran migrate/rollback + db:table"; `✔ b¹` annotated "I verified 4 request shapes"; a specialist `STATUS: done` was not treated as a `✔`; harvest `docs/delivery/tag/log.md` says "Coordinator verification found what the agent's own tests could not. The agent verified via Pest only. Pest auto-bypasses CSRF (`runningUnitTests()`)."

**The seed on the same prompt, pre-clause, did the thing the clause now forbids.** `20260804T202949Z/feature.log` stage f is "me" patching throttle + array-cast (`Edit` ×5 in `feature.cost.json`). It also did *not* treat the fixture auth hole as a specialist defect to re-brief: it raised a checkpoint and closed. Run 7's leftover `feature.log` is the same checkpoint, cheaper because it stopped ($3.53, 918s).

**Would a pre-1.42 orchestrator still have looped?** Not on the evidence we have. The 419/500 loop requires (i) real-HTTP verification that Pest will not catch, *and* (ii) "re-brief rather than patch" once that verification fails, *and* (iii) not stopping at the auth checkpoint the seed and run 7 both chose. (i) and (ii) are the 1.42 sentences. (iii) is the orchestrator applying "re-brief or escalate" to a Pest-green / HTTP-red stage instead of the checkpoint shape the Interface still allows ("Human decision needed → numbered options"). The fixture's missing `login` route is the *trigger*, not the *driver*: adding `route('login')` would turn the guest 500 into a redirect; it would not remove CSRF 419, and it would not restore the seed's cheap `Edit` ×5.

`agents/delivery-coordinator.md` already said "Never patch a subagent's work" (failed-stage step) before 1.42. That file is not in a command-driven run's context. The first seed's `Edit` ×5 is the empirical proof that the unloaded rule did not bind `/make-feature`.

### 4. Main $7.47 + specialists already exceeding billed $9.00 is the billed-vs-attributed gap, not a broken adder. The 19.7M "regression" is a work-volume / cache signal; run 9's cache split is missing

`scripts/eval-cost.py` module docstring (lines 24–32): **billed** is the CLI's `total_cost_usd` — "the run's cost." **attributed** is per-turn usage priced per agent — "never equals `billed`." `coverage_of_billed` is `attributed.usd / billed.usd` and "can exceed 1.0 when subagent turns are counted here but not in the result line's own usage" (`summarize()`, same file).

On-disk `feature.cost.json` files already show coverage > 1:

| Run | Billed | Attributed USD | `coverage_of_billed` |
| --- | ---: | ---: | ---: |
| First seed | $6.55 | $8.91 | 1.3608 |
| Run 7 `feature` | $3.53 | $7.06 | 1.9986 |
| Run 8 | $3.44 | $5.92 | 1.7196 |

Run 9's quoted attributed lanes (main $7.47 + backend $3.69 + database $0.70 + qa $0.59 = $12.45, tech-lead omitted) vs billed $9.00 is the same gap. A timeout run may also lack a `result` line, in which case `eval-cost.py` `_billed()` returns `usd: None` — [run 9](2026-08-18-run-9.md) still quotes **$9.00 billed**, so a `result` line with `total_cost_usd` existed or the write-up took the printed `cost:` line from a partial ledger. The per-class token split for run 9 is **not recoverable** without `feature.cost.json`.

**Tokens vs dollars on the seed.** First-seed attributed: `cache_read_tokens` 10,383,232 / 11,189,642 = **92.8% cache reads**. Cache reads + both write tiers = 11,187,392 / 11,189,642 = **99.98% cache of some class**. Raw input+output is 2,250 tokens. `baseline.json` `_tokens_caveat` already says run-6 totals were >99% cache-read and that `max_tokens` "tracks context volume × turns far more than it tracks spend." Run 8 on disk: 6,470,359 / 7,232,113 = 89.5% cache reads.

Run 9 attributed tokens 19,725,180 / seed 11,189,642 = **1.76× tokens** against **1.37× billed**. That ratio — tokens up more than dollars — is the cache-read signature the `_metrics` note exists to prevent us from misreading. We cannot quote run 9's cache_read count. We can say every surviving `feature.cost.json` is 89–93% cache reads, and the 19.7M ceiling breach is not evidence of 1.76× generation.

### 5. 10/10 after timeout is real for harvest-on-disk, false-confidence for the closing-contract greps

[Run 9](2026-08-18-run-9.md): `$LOG` is `eval-cost --text-only`, falling back to concatenated assistant text when there is no `result` line; `VERIFIED` / `NOT-CHECKED` passed because they appear as the **tech-lead return quoted into the reconstructed log**, not as the orchestrator's own final six-field close. `$FULL_LOG` (main-thread only, `full_text()`) ends mid-board at `Wai`.

That fallback is documented, not new. `scripts/eval-cost.py` `final_text()`: a timed-out run never emits a `result` line, so it concatenates assistant text. [Run 7](2026-08-06-run-7.md) addendum (the 1204s / $4.49 teach-delivery timeout): `$LOG` fallback is "deliberately unfiltered by agent, unlike `$FULL_LOG`," and a timeout can make the two files diverge once a subagent's text lands. Run 9 is that divergence: specialist `VERIFIED` / `NOT-CHECKED` satisfied `check_log`, which is what `checks_feature()` uses for the closing-contract pair (`run-evals.sh` lines 453–454).

**Harvest is not in that trap.** `checks_feature()` harvest checks are `check_file` / `check_file_under` on the workdir. [Run 9](2026-08-18-run-9.md) quotes the files as read on the kept workdir: `docs/team/stack.md` dated 2026-08-18 during `/make-feature Tag --api`; `docs/delivery/tag/log.md` naming CSRF / `Accept`-dependent behaviour. Those two of the 10 are artifact-true.

**Adoption-receipt risk.** A receipt that says "10/10 including harvest" over-claims if it implies the orchestrator closed the Interface contract. Harvest held. The closing-contract greps held on the wrong speaker. The same observability gap [run 8](2026-08-12-run-8.md) filed — no derived subagent-inclusive log; do not re-add `check_stage_return_shape` — is what made the wrong-speaker pass possible. Acceptable as a harvest proof; not acceptable as proof of a coordinator close.

### 6. `feat/agent-cost-instrument` would not have changed run 9's *measurement*. It is crash-resilience already merged, plus a superseded pricing approach

Worktree `.claude/worktrees/agent-cost` @ `63c1591` (`feat/agent-cost-instrument`). Merge-base with `main` is `8f969cf` (the plan commit). Unique commits on the fork: `5edb23c`, `4c0599c`, `9b00a9d`, `57d0fe8`, `63c1591`. The shipped plan (`docs/superpowers/plans/2026-08-04-agent-accuracy-and-cost.md`, "The parallel implementation — resolved 2026-08-04") already records what was taken and what was left:

- Taken into v1.31.1: non-dict JSON lines must not crash the parser; async subagents must stay visible; ratchet dollars as well as tokens.
- Left: the fork concluded per-agent cost cannot come from the transcript and moved attribution to the board feed, tokens-only. The plan calls that a **probe artifact** (Task 1 captured only a non-delegating prompt). Status line in that plan: "Nothing further is pending from it; its remaining commits are the superseded pricing approach."

Direct file diff: main `scripts/eval-cost.py` is 506 lines (per-turn attribution, rate-table reconcile, `full_text()` main-thread filter). The fork's copy is 231 lines (result-line dollars + board-feed token totals). The fork's `final_text()` fallback appends `_text_of(obj)` for **every** parsed object, not `type == assistant` only — the false-PASS path the shipped parser's docstring exists to prevent.

Merging the fork would not have changed run 9's billed $9.00 (that number is the CLI's `total_cost_usd`). It would not have produced a more precise 19.7M. It would have dropped per-agent input/output/cache splits and, on timeout, risked a worse `$LOG` fallback.

## Root-cause hypothesis

Run 9 exceeded `$8.50` / `14.5M` tokens and hit `EVAL_TIMEOUT` because v1.42.0's Interface clause bound a command-driven `/make-feature` for the first time: the orchestrator verified stage (b) on the real HTTP kernel (Pest-green, CSRF/419 + missing-`login` 500), then re-briefed instead of applying the seed's cheap main-thread `Edit` ×5 or the seed/run-7 auth checkpoint. Four `SendMessage` fix rounds on that fixture hole, plus verify Bash 16→36, are the billed $2.45 over the seed and the token-volume jump. Independently, `max_seconds` 1900 was seeded from a 1456s success that already required `EVAL_TIMEOUT` > 1200; the default kill cannot observe a seed-shaped close, which is why 1203s reads `within` 1900s and `TIMED OUT` at once. This is not a model-tier, body-length, or qa-engineer-tuning problem, and it is not a reason to treat run 8's $3.44 as the prior.

**What would falsify it.** A billed `feature` run on the same 1.42 Interface, same fixture, that finishes with no 419/500 re-brief loop and still bills >$8.50 would say the extra verify-before-advancing work *alone* is the new shape. A run that loops the same 419/500 after a `login` route is added would say the fixture trigger is not the missing name. A run under `EVAL_TIMEOUT≥1900` that still has no coordinator close at 1900s would say the missing close is not the 1200s kill.

## Ranked next actions

Rejected without a new milestone: model-tier changes, body slimming, qa-engineer tuning ([Prove-it spec](../superpowers/specs/2026-08-06-prove-it-milestone-design.md) "What this milestone does not do"; [accuracy-and-cost spec](../superpowers/specs/2026-08-04-agent-accuracy-and-cost-design.md) same). The evidence points at contract × fixture × timeout split, not at those levers.

1. **Do not raise `max_usd` / `max_tokens` now.** [Run 9](2026-08-18-run-9.md) already recorded the regressions as "the shape, not a reason to raise the ceiling in this task." Absorbing $9.00 would freeze a three-round 419/500 loop as the new normal.
2. **Do not merge `feat/agent-cost-instrument`.** Finding 6: crash-resilience is already on `main` (v1.31.1); remaining commits are the superseded board-feed approach.
3. **Do not re-run a billed `feature` before 1.43.0 Adoption ships.** Estimated **$8–10**. Same fixture + same contract + `EVAL_TIMEOUT=1200` re-confirms the timeout. `EVAL_TIMEOUT=1900` on the same fixture likely completes a close and may add dollars, not remove them. One post-Adoption run can pin whatever 1.43 touches *and* re-measure cost. A run now spends the same money twice.
4. **After 1.43.0, one billed `feature` with `EVAL_TIMEOUT ≥ 1900` and `max_usd` left at $8.50.** That is the smallest experiment that can see a coordinator close and still let dollars vote. See [the follow-up plan](../plans/2026-08-19-run-9-cost-next.md). If that run lands ≤$8.50 without a 419/500 loop, the ceiling stays and finding 1 is confirmed. If it exceeds $8.50 with no loop, *then* 1.42 verify-before-advancing is the new shape and a reseed is an argument, not an absorption.
5. **Do not add a fixture `login` route as a 1.42 follow-up.** It converts the guest 500 into a redirect. It does not remove CSRF 419, and the seed already completed without it via `routes/api.php` + a checkpoint (`20260804T202949Z/feature.log`).
6. **Subagent-inclusive derived log — keep as run 8's own plan.** [Run 8](2026-08-12-run-8.md) "What this leaves open." It would have made run 9's wrong-speaker `VERIFIED` visible. It would not have changed $9.00 or the timeout. Not this write-up's implementation.

**Recommendation:** (1)+(2)+(3) now; (4) as the next billed action after Adoption. That is not "do nothing" on the cost question — it is one deferred experiment with a falsifier, instead of raising a ceiling or paying for a same-shape re-run.
