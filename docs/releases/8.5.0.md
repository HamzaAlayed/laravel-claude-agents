# Laravel Guild 8.5.0

## What’s new

Pull-request feedback now returns to the stage that owns it. CI failures route
by exact declared check name, review comments route by the longest matching
owned path, and every event remains visible through repair and resolution.

- Typed stages declare globally unique `feedback_checks`.
- `guild feedback list` exposes routes and the durable event ledger.
- `guild feedback assign` lets the main thread resolve an unknown CI owner.
- Generated `feedback.md` records each source, route, owner, status, and
  resolution attempt.
- Multiple comments and checks for one stage share one bounded repair attempt.
- The PR watcher continues after initial completion while the recorded PR is
  open.

See [Route PR and CI feedback](../feedback-routing.md) for the complete
operating procedure.

## Breaking changes

Automation that supplied `ingest --stage` as the routing decision must now
declare `feedback_checks` during planning. `--stage` remains accepted only as
an optional assertion and fails when it disagrees with kernel-derived
ownership.

Review comments must include a GitHub file path owned by one stage. Unmatched
events no longer fall back to the last writer; they become `route_required`
and pause new dispatch until the main thread establishes a valid route.

## Fixes

- Feedback no longer reaches an unrelated stage because it happened to write
  last.
- Duplicate webhook or polling observations no longer consume retries.
- Multiple feedback items discovered during one repair no longer create
  multiple attempts.
- A successful report resolves all open feedback attached to that stage.
- A new event after retry exhaustion stops instead of silently reopening an
  unbounded loop.

## Compatibility

Legacy delivery state loads with empty feedback fields. Direct point work is
unchanged. Existing plans without `feedback_checks` can still load, but an
unmapped CI failure requires an explicit main-thread assignment before work
continues.

## Verification

- Focused feedback tests cover automatic routing, assertions, unresolved
  routes, assignment authority, grouped repairs, resolution, idempotency,
  exhaustion, compatibility, generated views, watching, and CLI behavior.
- Full kernel tests cover interactions with retries, reports, budgets,
  approvals, recovery, and workplace state.
- Console tests verify that stage selection is optional and cannot replace
  kernel routing.
- Guardrails bind all nine pipeline commands and the delivery coordinator to
  the same feedback lifecycle before publication.
