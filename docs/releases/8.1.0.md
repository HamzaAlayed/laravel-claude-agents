# Laravel Guild 8.1.0

## What’s new

Human checkpoint questions and answers now survive interruption as kernel
state. Before asking, the main thread records the exact prompt, risk, typed
options, and recommendation with `guild checkpoint open`. The answer is then
recorded with `guild checkpoint resolve`, including user provenance, action,
optional constraint note, and UTC timestamp.

- `guild checkpoint list` is the resume entry point.
- Pending checkpoints pause only their stage; independent lanes keep moving.
- A `continue` answer requeues the lane with its durable note.
- A `stop` answer fails the lane and stops the delivery.
- `claim`, `report`, and delivery completion fail while a checkpoint is pending.
- `docs/delivery/<name>/checkpoints.md` provides a generated readable history.

The full lifecycle and command examples are documented in
[Durable human checkpoints](../checkpoint-policy.md).

## Compatibility

This is an additive release. Existing delivery state without checkpoint fields
loads with an empty checkpoint list and empty per-stage checkpoint ID. No
synthetic prompt or answer is created.

Orchestrators should add one resume step: call `guild checkpoint list` before
`ready`. A pending record must be presented exactly as stored, and a resolved
record must not be asked again.

## Verification

- Kernel units cover exact prompt persistence, typed option validation,
  idempotent open and resolve, user-only authority, stage-local pause,
  independent lane progress, stop behavior, and legacy state loading.
- CLI units exercise checkpoint open, list, and resolve end to end.
- Guardrail tests prove main-thread checkpoint commands are allowed while the
  same subagent commands are denied.
- Static orchestration ratchets bind all nine commands and the coordinator to
  open-before-ask, exact resume, no re-ask, and independent-lane behavior.
- The full kernel, console, eval, guardrail, generated-target, manifest, shell,
  and frontend release gates pass before the tag is published.
