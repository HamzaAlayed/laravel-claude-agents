# Laravel Guild 9.1.0

## What’s new

Laravel Guild now requires measurable proof for declared performance outcomes.
The outcome benchmark harness compares repeated, read-only baseline and
candidate captures and produces a source-bound receipt that the guild kernel
re-verifies before a stage can complete.

- Query objectives prove a real median reduction without query-p95 regression.
- Latency objectives use p95 improvement and reject increased query tails.
- All objectives require equivalent response, database, event, and job hashes.
- Receipts bind the exact source files, thresholds, summaries, verdict, and
  receipt hash.
- A dedicated `outcome benchmark` CI job exercises the comparator and kernel
  integration before immutable publication.

See the [outcome benchmark runbook](../outcome-benchmark.md) for capture format,
commands, thresholds, and failure recovery.

## Breaking changes

A stage criterion claiming fewer queries or lower latency while preserving
behavior must be listed in
`benchmark_criteria` and verified with the `outcome-benchmark` runner. A generic
test or file-existence record no longer satisfies that declared criterion.

No existing stage becomes benchmark-required automatically. Existing delivery
state loads with an empty `benchmark_criteria` list.

## Fixes

- Performance success can no longer be inferred from one manual timing, an
  average, or prose in a stage report.
- Query reductions that change observable behavior now fail even when faster.
- Database-writing, undersampled, unstable, path-escaping, tampered, and
  source-drifted evidence is rejected.
- Baseline and candidate captures cannot silently use different datasets,
  runtimes, scenarios, or objectives.

## Compatibility

Claude, Cursor, Codex, Gemini, and classic installs retain the v9 delivery
lifecycle. The comparator uses Python's standard library and does not execute
Laravel, database commands, migrations, or destructive operations.

Capture production remains application-specific. The operator remains
responsible for representative data and complete instrumentation, and raw SQL,
responses, rows, event/job payloads, and secrets must not enter benchmark
artifacts.

## Verification

- Eighteen outcome benchmark tests cover all three objectives, behavior drift,
  writes, sampling, path containment, tampering, source drift, stage planning,
  runner binding, and literal argv execution.
- The full 209-test guild-kernel suite remains green with backward-compatible
  loading and fail-closed benchmark enforcement.
- The enforcement map now publishes 15 controls, including the benchmark's
  runtime, CI, operator, prompt, and trust boundaries.
- Immutable release publication requires all 16 named hosted jobs for the exact
  v9.1.0 commit.
