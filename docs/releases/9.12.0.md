# Laravel Guild 9.12.0

Rolling parallel scheduling

## What’s new

- `/make-feature` splits work into smaller, independently verifiable tasks.
  Each task declares its output, owned paths, and actual prerequisites.
- The planner prioritizes tasks that unblock longer dependency chains. When
  a prerequisite passes verification, the coordinator can fill the next
  open slot while unrelated work is still running. A plan can run up to four
  distinct specialists concurrently.
- A specialist can take several tasks in sequence. Each stage gets its own
  report, so evidence from one task stays attached to that task.

## Breaking changes

None.

## Fixes

- Parallel planning detects overlapping parent and child paths when no
  dependency orders the writes.
- A pending stage approval or checkpoint leaves independent approved tasks
  eligible to run. Dependent tasks wait for verified prerequisites.

## Compatibility

`ready` exposes the exact `report_path` to include in each task brief. Plans
can use `<agent>--<stage-id>.md` to distinguish reports from the same
specialist. The `<agent>.md` form remains valid when it identifies one stage.
[Coordination guide](https://github.com/HamzaAlayed/laravel-claude-agents/blob/v9.12.0/docs/multi-agent-coordination.md)

## Verification

Three matched live trials per scheduler used the same Sonnet 5.5 prompts and
the same four-task Tag API fixture. The baseline was Laravel Guild 9.11.2
(`920df9f`). Cost is the USD total reported by Claude Code for each trial.
Quality checks covered the API contract, validation rules, the QA matrix,
and its review.

| Metric | Previous scheduler | Rolling scheduler |
| --- | ---: | ---: |
| Median delivery time | 17.56 s | 17.28 s |
| Median backend task start | 10.92 s | 3.84 s |
| Median Claude Code cost per trial | $0.0333 | $0.0324 |
| Quality checks passed across three trials | 39/39 | 39/39 |

Median delivery time decreased 1.6% in this fixture. Backend work started
before the independent QA matrix finished in all three rolling trials.

In a separate live checkpoint probe, the QA matrix and its review both passed
verification while the API contract was paused. The backend task stayed
queued until the checkpoint cleared and the contract passed verification.
The probe passed 13 of 13 quality checks.
