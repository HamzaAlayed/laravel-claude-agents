# Laravel Guild 8.3.0

## What’s new

Stage retries now use an explicit, auditable lifecycle. A failed attempt is no
longer moved directly back to `running`. The kernel requeues it, requires a new
atomic claim, and records why the retry exists.

- `guild retry request` records a typed source, exact reason, and stable event
  ID after completion telemetry.
- `guild retry list` shows whether each failure requeued or stopped the lane.
- `guild transition list` shows every kernel-owned stage status change.
- `ready` includes the next attempt number and retry context for the new brief.
- Generated `retries.md` and `transitions.md` views preserve the audit trail.
- Duplicate event delivery is idempotent.
- The second distinct failure marks the stage `failed` and stops the delivery.

The full lifecycle is documented in
[Auditable stage retries](../retry-policy.md).

## Fixed

A queued stage previously could submit a report without passing through the
normal claim path. CI or review feedback also moved a completed stage directly
to `running` and created a claim timer without rechecking dispatch constraints.
Retry exhaustion could then stop the delivery while leaving the lane marked
`done`.

This release rejects reports from queued or completed stages, routes every retry
through `ready` and `claim`, invalidates stale evidence, and makes the terminal
stage and delivery statuses agree.

## Breaking changes

Documented delivery flows are unchanged: they already call `ready`, `claim`,
record completion telemetry, and then `report`. Any custom automation that
reported an unclaimed stage must add the missing `claim` and telemetry steps.
The kernel now rejects that unsupported shortcut.

## Compatibility

Existing `kernel.json` files load with empty retry and transition ledgers. A
conservative attempt count is derived from legacy status and reopen fields; no
historical event is invented. Direct specialist work outside a planned
delivery remains unchanged.

## Verification

- Focused retry-policy tests cover legal transitions, claim enforcement,
  telemetry preservation, authority, idempotency, retry exhaustion, legacy
  state, generated views, and CLI inspection.
- The full kernel suite covers the stricter report contract across criteria,
  pairing, workplace feedback, checkpoints, budgets, and loop detection.
- Guardrail ratchets bind the shared harness, nine pipeline commands, and the
  delivery coordinator to the explicit retry lifecycle.
- The complete console, eval, manifest, generated-target, shell, guardrail, and
  frontend release gates pass before publication.
