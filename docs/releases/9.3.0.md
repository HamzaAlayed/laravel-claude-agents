# Laravel Guild 9.3.0

## What’s new

Laravel Guild now builds one bounded, stage-specific context packet between
claim and specialist dispatch. The packet combines non-trimmable kernel
authority with narrowly selected, hash-bound repository excerpts, then records
its token estimate, omissions, state hash, source hashes, and packet hash.

- `guild context build` creates the packet atomically.
- `guild context verify` rejects stale, oversized, unsafe, or tampered context.
- `guild context show` verifies before displaying the packet.
- Mandatory objective, approvals, ownership, budgets, criteria, current state,
  and output contract cannot be trimmed.
- Optional excerpts are omitted only as whole units from lowest priority; a
  required excerpt that does not fit stops dispatch.
- Recovery produces a fresh packet with completed dependencies and durable
  retry, recovery, feedback, and next-action state.

See [How does Laravel Guild build bounded agent context?](../context-engineering.md)
for the exact specification, workflow, safety boundary, and recovery guide.

## Breaking changes

There are no data-format or installation breaks for existing deliveries.
Coordinated agent runs gain one required pre-dispatch step: after `claim`, build
and verify the claimed lane's context packet before giving it to the specialist.
Legacy direct-agent usage remains available but does not receive this delivery
context guarantee.

Context specifications are deliberately strict. Unknown fields, partial source
records, absolute paths, traversal, symlinks, and excluded dependency or
environment paths are rejected rather than ignored.

## Fixes

- Mandatory constraints can no longer disappear when optional source context
  fills the packet budget.
- Source excerpts are never silently cut in the middle; omissions are explicit
  and reviewable.
- A source edit, context-spec edit, delivery-state transition, or packet edit
  invalidates the prior packet instead of serving stale working memory.
- Resumed agents receive durable completed-work and recovery state rather than
  relying on the remaining conversation window.

## Compatibility

The context runtime uses only Python's standard library and ships through the
existing Claude, Cursor, Codex, Gemini, and classic installers. Packet schema 1
works with the v9 kernel state and does not change stage result files or the
Composer capture-adapter API. The Laravel package can be installed from the
v9.3 tag with `hamzaalayed/laravel-guild-benchmark-capture:^9.3`.

The deterministic token estimate is a portable byte-based budget, not an exact
model tokenizer. Packet delivery itself remains an orchestration requirement:
the runtime proves construction and verification but cannot prove that every
supported external host supplied the packet to its model.

## Verification

- Sixteen stdlib unit tests cover bounded construction, whole-source omission,
  mandatory overflow, stage isolation, prompt-injection labeling, authority
  spoofing, tampering, stale source/spec/kernel state, secrets, traversal, and
  symlinks.
- All existing kernel tests continue to pass without changing stage behavior.
- The canonical context rule is generated into all ten orchestration carriers,
  and its coordinator-surface change has a dated no-ceiling-change eval waiver.
- The enforcement map publishes 17 controls with the context runtime's honest
  prompt boundary.
- Immutable publication requires all 18 named hosted jobs for the exact v9.3.0
  commit.
