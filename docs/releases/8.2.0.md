# Laravel Guild 8.2.0

## What’s new

Claimed specialists now stop when they repeat the exact same tool-call cycle
three times. The detector catches cycles from one to four calls long and denies
the call that would complete the third repetition.

- A repeated single command such as the same unchanged test invocation stops.
- Multi-call cycles such as read → test → read → test also stop.
- A changed tool or input breaks the exact-match pattern.
- `guild loop list` exposes durable loop evidence.
- `docs/delivery/<name>/loops.md` provides a generated human-readable view.
- The failed lane and stopped delivery remain visible on the normal board.

The behavior and its exact-match boundary are documented in
[Unproductive-loop detection](../loop-policy.md).

## Privacy

The runtime hashes the tool name and canonical JSON input. Kernel state stores
the digest, tool name, and timestamp, but never stores the raw input in loop
history. Per-stage history is limited to 24 entries.

## Compatibility

This is an additive runtime guard. Existing delivery state loads with empty
loop history and no loop events. Direct specialist work outside a claimed
kernel stage is unchanged.

After a loop stop, do not retry the same sequence or only raise its budget. A
new attempt must use a changed brief or plan that addresses the lack of progress.

## Verification

- Kernel units cover one-step and multi-step cycles, changed-call breaks,
  duplicate hook events, bounded cycle length and history, privacy, claim
  resets, legacy state, CLI output, and pre-execution hook denial.
- Guardrail ratchets bind all nine pipeline commands and the coordinator to
  inspect loop evidence, stop dispatch, and reject unchanged retries.
- The full kernel, console, eval, guardrail, generated-target, manifest, shell,
  and frontend release gates pass before the tag is published.
