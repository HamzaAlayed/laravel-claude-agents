# Laravel Guild 9.8.0

Multi-Agent Architecture & Coordination

## What’s new

- A deterministic coordination planner chooses `single-agent`, `delegate`, or
  `hold`, then emits bounded parallel, pipeline, or hybrid waves with typed
  handoffs. See [When should work use multiple agents?](../multi-agent-coordination.md).
- Capability routing covers all 18 registered agents while cycles, missing
  approvals, missing capabilities, unordered write collisions, and duplicate
  logical side effects fail before dispatch.
- Source-bound comparison receipts require representative single-agent and
  multi-agent runs before delegation becomes the accepted default.

## Breaking changes

None. Existing delivery graphs remain valid. Teams adopting the new gate should
create a coordination workload and comparison baseline before treating a
multi-agent topology as preferred.

## Fixes

- Tiny or sequential work no longer receives a multi-agent recommendation when
  coordination overhead erases the predicted gain.
- One agent cannot be double-booked inside one emitted wave.
- Completed lanes are explicitly preserved after interruption while failed
  lanes are contained and successful work is not replayed.

## Compatibility

- The harness uses Python 3 standard-library modules only.
- Receipt and policy schemas start at version 1.
- The shared 18-agent registry and all Claude, Gemini, Cursor, and Codex
  orchestration carriers remain synchronized.
- No dependency, database schema, or application-runtime change is required.

## Verification

- 10 registered coordination scenarios cover useful delegation and fail-closed
  planning outcomes.
- 22 focused tests cover scheduling, handoffs, conflicts, receipts, evidence
  drift, and measured value decisions.
- The required `multi-agent coordination` hosted-CI job validates the policy,
  replays all scenarios, and runs the focused suite.
- The enforcement map now names 22 controls, and immutable publication requires
  23 named hosted-CI jobs for the exact release commit.
