# Laravel Guild 9.0.0

## What’s new

Laravel Guild now publishes an explicit, machine-verifiable answer to “what is
actually enforced?” Fourteen engineering-loop controls identify their runtime,
pre-tool-hook, CI, operator, and prompt boundaries without treating agent prose
as a hard guarantee.

- `config/enforcement-map.json` is the versioned source of enforcement claims.
- `docs/enforcement-map.md` is its deterministic operator-facing reference.
- Every control names implementation files, executable evidence, required CI,
  its safe failure mode, the operator’s action, and a known limitation.
- `scripts/check-enforcement-map.py` rejects incomplete inventories, unsafe or
  missing paths, prompt-only guarantees, unknown CI jobs, and stale docs.
- A separate required `enforcement map` CI job tests and validates the contract
  before immutable publication.

See the [engineering-loop enforcement map](../enforcement-map.md) for the full
control inventory and failure runbook.

## Breaking changes

Contributors must update `config/enforcement-map.json` when an enforcement
boundary, implementation path, evidence path, CI owner, failure mode, or known
limitation changes. `docs/enforcement-map.md` is generated and must not be
edited independently. Release publication now requires the `enforcement map`
job in addition to the previous 14 hosted gates.

There is no breaking change to existing delivery state or lifecycle commands.

## Fixes

- Strong harness claims can no longer exist only as scattered narrative.
- Prompt instructions are explicitly separated from runtime and host controls.
- Evidence paths must stay inside the repository and resolve to regular,
  non-symlink files.
- CI evidence must name a job already required by the immutable release
  harness, preventing advisory checks from being described as publication
  gates.
- Generated documentation drift now fails with an exact repair command.

## Compatibility

Claude, Cursor, Codex, Gemini, and classic installs keep the v8.9 delivery
state schema and commands. The enforcement map describes the existing v8
runtime controls plus their trust boundaries; it does not silently widen tool
authority or mutate an application database.

The map does not claim protection against arbitrary same-account code
execution, unsupported hosts that omit hooks or telemetry, unknown attacks,
or the quality of a human approval. Those boundaries remain visible in every
generated release of the document.

## Verification

- Six focused enforcement-map tests cover deterministic rendering, the exact
  14-control inventory, executable evidence, path containment, release-gate
  membership, prompt-only rejection, and the checker CLI.
- The guardrail harness asserts the manifest, required CI job, release gate,
  focused suite, and README entry remain wired together.
- The release harness requires all 15 named hosted jobs for the exact v9.0.0
  commit before creating its annotated tag and release receipt.
