# Laravel Guild 9.4.0

## What’s new

Laravel Guild now carries a small, reviewed memory across deliveries without
turning transcripts into authority. Agents can propose typed candidates;
main-thread approval promotes them into a hash-sealed store, and bounded
retrieval selects only records that are approved, unexpired, evidence-current,
relevant, and visible to the target agent.

- Four memory types separate user decisions, project facts, procedures, and
  useful delivery episodes.
- Project scope and exact-agent scope prevent unrelated specialist leakage.
- Non-user records require hash-bound repository evidence.
- Conflicts require explicit supersession rather than last-write-wins.
- Deletion is a two-step approval that preserves an auditable tombstone.
- Context packet schema 2 injects retrieved memory as untrusted data and binds
  packet validity to the current memory-store hash.

See [How does Laravel Guild remember the right things safely?](../memory-engineering.md)
for the lifecycle, commands, safety boundary, and recovery guide.

## Breaking changes

Context packets now use schema 2 and require `config/memory-harness.json` plus
`docs/team/memory.json`. Existing schema-1 packets must be rebuilt before
dispatch. Existing delivery kernel state, stage result files, and benchmark
receipts are unchanged.

Approval-class memory operations are intentionally main-thread-only. A
specialist may propose a candidate or request deletion, but it cannot approve,
supersede, or execute deletion on its own.

## Fixes

- Durable knowledge no longer depends on unbounded conversation history.
- Stale evidence, expired records, candidate records, irrelevant records, and
  wrong-agent records are withheld with explicit reasons.
- A store mutation invalidates already-built context packets instead of letting
  a stage continue with an outdated memory snapshot.
- Optional memory is removed only as a whole record; mandatory user decisions
  stop construction if they cannot fit.

## Compatibility

The memory runtime uses Python's standard library and ships through the existing
Claude, Cursor, Codex, Gemini, and classic installers. It adds no database
migration and does not alter Laravel application behavior. New installs start
with an empty, valid memory store.

Installed pre-tool enforcement is host-specific. On runtimes without the
Claude Code hook, operators must use the `guild memory` commands and preserve
main-thread authority themselves. The hashes detect partial or accidental
drift; they are not cryptographic signatures against a process that can rewrite
the runtime and all evidence as the same operating-system account.
