# Laravel Guild 9.5.0

Evaluation Engineering

## What’s new

Laravel Guild can now say why an agent change is better—or refuse to say so
when the evidence is incomplete. Every live-agent scenario is registered as a
machine-readable case with a representative prompt, expected outcomes,
forbidden outcomes, minimum deterministic coverage, and the operational
metrics that matter for comparison.

Each billed case now produces a source-bound receipt containing its execution
status, deterministic result, duration, token volume, billed cost, tool-call
count, budget decision, and evidence hashes. Receipts can be independently
verified and compared only while their evaluator, registry, budget, and case
definition remain identical.

See [How do we know an agent change got better?](../evaluation-engineering.md)
for case selection, exact commands, trust boundaries, and recovery.

## Breaking changes

There is no application-facing breaking change. The evaluation verdict is
stricter: a nonzero or timed-out live-agent process now fails even if its
partial output happens to satisfy all deterministic checks. Scripts consuming
results should use `<case>.receipt.json` as the verdict authority.

Case prompts and descriptions now come from `config/evaluation-cases.json`.
Extensions must register the case, budget, rubric branch, deterministic checks,
and shell suite membership together.

## Fixes

- Expected and forbidden behavior is explicit instead of living only in prose.
- Shell case lists, registry entries, checks functions, and budgets must remain
  exactly aligned.
- A rubric judge cannot change PASS or FAIL; disagreement remains useful
  advisory evidence.
- Missing cost data, missing artifacts, lost deterministic coverage, process
  failure, timeouts, hard-ceiling breaches, and material metric regressions all
  fail closed.
- Receipt verification detects content edits, stale contracts, changed source
  files, unsafe paths, and symlink substitution.

## Compatibility

The evaluator uses Python's standard library and installs through the existing
Claude, Cursor, Codex, Gemini, and classic project targets. No Laravel database
migration or runtime application change is required.

Live model execution remains opt-in and billed. The new hosted CI job tests the
evaluator and recorded fixtures without making model calls. Historical result
folders remain readable, but they do not acquire receipts retroactively and
cannot be compared as schema-1 evidence.

## Verification

- Twelve focused evaluation-harness tests cover registry synchronization,
  passing and failing receipts, minimum coverage, process failure, budgets,
  judge authority, tamper detection, source drift, symlinks, privacy, CLI
  behavior, and four-dimensional regression comparison.
- Existing eval-cost, budget, coordinator-hash, deterministic trace-replay,
  guardrail, installation, and release tests remain required.
- The generated enforcement map publishes 19 controls.
- Immutable publication requires all 20 named hosted jobs for the exact v9.5.0
  commit and retains the release receipt.
