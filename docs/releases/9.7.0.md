# Laravel Guild 9.7.0

Agent Reliability & Operations

## What’s new

Laravel Guild now turns recorded baseline and canary operations into one
source-bound operational health receipt. The deterministic decision is
`promote`, `hold`, or `rollback` based on completion, p95 latency, p95 cost,
human intervention, recovery, safety, duplicate side effects, circuit state,
and material change from the accepted baseline.

Nine failure-injection scenarios exercise unavailable tools, timeouts, rate
limits, partial outages, corrupt state, retry exhaustion, interruption after a
committed side effect, duplicate effects, and safety violations. See
[How do we keep an agent dependable after release?](../agent-reliability-operations.md)
for evidence format, exact commands, canary policy, circuit behavior, rollback,
limitations, and incident recovery.

## Breaking changes

None. Existing agent execution continues unchanged until an operator integrates
recorded cohort evidence into a release process.

Reliability receipts deliberately do not deploy, route traffic, reset a circuit,
or perform database actions. Platforms adopting this gate must treat `hold` as
no promotion and `rollback` as an operator-controlled restoration request.

## Fixes

- Successful demonstrations can no longer serve as operational proof when the
  representative cohort breaches success, latency, cost, intervention,
  recovery, safety, or idempotency expectations.
- A broad absolute ceiling can no longer hide a material regression from a
  healthier accepted baseline.
- Interruption recovery now has executable evidence that a committed side
  effect is deduplicated rather than applied twice.
- Tampered receipts, stale sources, unsafe paths, symlinks, malformed attempt
  sequences, and automatic database rollback policy fail closed.

## Compatibility

The reliability engine uses Python's standard library and reads repository-
local JSON evidence. It requires no model call, network access, Laravel
application write, database query, migration, or new dependency.

The repository cannot route production traffic or terminate arbitrary host
processes. Operators must connect the receipt decision to their own deployment
platform and ensure traffic and telemetry are representative.

## Verification

- Eighteen focused tests cover healthy promotion, insufficient evidence,
  unhealthy baselines, absolute SLO failures, material regression, duplicate
  side effects, idempotent interruption recovery, circuit opening, privacy,
  path safety, tampering, source drift, and rollback authority.
- Nine versioned degraded-condition scenarios replay with exact safe decisions,
  circuit states, and applied-side-effect counts.
- The shared harness and ten generated orchestration carriers bind the same
  reliability policy.
- The generated enforcement map publishes 21 controls.
- Immutable publication requires all 22 named hosted-CI jobs for the exact
  v9.7.0 commit and retains the release receipt.
