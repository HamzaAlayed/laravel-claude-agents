# Laravel Guild 8.8.0

## What’s new

The engineering loop now attacks its own trust boundaries before every
release. A versioned matrix runs 18 hostile scenarios and checks each exact
safe post-state, including no state changes or outside writes when denial must
be side-effect-free.

- Traversal and symlink attacks target delivery, sprint, lesson, and report
  paths.
- Evidence, approval, telemetry, budget, loop, retry, feedback, stale-report,
  identifier-injection, and concurrent-claim attacks exercise lifecycle rules.
- A separate `adversarial engineering loop` CI job is required for release
  publication.

See [adversarial engineering-loop testing](../adversarial-testing.md) for the
threat boundary, case families, local command, and failure runbook.

## Breaking changes

Unsafe orchestration inputs that were never part of the documented contract
now fail closed:

- Delivery, sprint, and stage identifiers must begin with a letter or number,
  use only letters, numbers, `.`, `_`, or `-`, and be at most 128 characters.
- A stage report must be a regular `.md` file directly inside
  `docs/delivery/<name>/stages/`; symlinks and reports from other directories
  are rejected.

If an unpublished local delivery used an unsafe identifier, create a new safe
delivery slug and re-plan it. Do not rename or hand-edit `kernel.json`.

## Fixes

- Delivery and sprint name traversal no longer creates state outside the
  project.
- Symlinked delivery, sprint, and lesson directories no longer redirect kernel
  files outside the project.
- A valid-looking report from an unrelated or symlinked path no longer runs
  verification or marks a stage complete.
- Control characters can no longer enter stage IDs and generated trace views.

## Compatibility

Existing safe delivery and sprint slugs, normal stage IDs, and canonical stage
reports continue to work. Claude, Cursor, Gemini, Codex, and classic installs
receive the same hardened kernel. The attack suite uses only Python's standard
library and performs no billed model calls.

## Verification

- Nineteen adversarial tests cover all 18 manifest cases and manifest-to-suite
  parity.
- The existing 209 kernel tests pass after the containment changes.
- Shell guardrails, release automation, manifests, generators, budgets,
  console, eval parser, UI, and strict frontmatter gates pass.
- GitHub-hosted CI includes the new required adversarial job for the exact
  release commit.
