# Laravel Guild 9.13.0

Stage timing and live scheduler benchmarks

## What’s new

- Run `guild observe timing` to see when each stage became eligible, was
  claimed, started, returned, and passed verification. The delivery’s
  `observability.md` shows the elapsed intervals and resolved checkpoint waits.
- Claude Code lifecycle hooks record worker starts and finishes in the
  delivery trace. The timing view shows each retry as a separate attempt.
- The live evaluation runner compares one agent, the v9.11.2 wave scheduler,
  and rolling dispatch under the same artifact checks.

## Breaking changes

None.

## Fixes

- Timing uses verified dependency completion and approval events to distinguish
  time eligible for dispatch from time spent waiting on a checkpoint.
- Duplicate worker lifecycle events and late returns from an earlier attempt
  leave the current attempt’s timing intact.

## Compatibility

Existing delivery traces remain readable. Intervals with missing timestamps
are shown as unavailable. Workers on hosts without lifecycle events can
still produce claim and verification timings.

## Verification

The comparison ran 36 live Sonnet 5.5 trials across four synthetic Laravel
workloads. It verified 35 deliveries at a total reported cost of $0.82277.
Both parallel modes beat one agent on all three independent-task matches.
On the checkpoint hybrid, rolling dispatch reduced median rules-stage
eligibility-to-claim time from 2.04 seconds to 6.33 milliseconds, and
median delivery time from 16.47 to 15.49 seconds. All modes passed all 39
hybrid checks. One sequential single-agent response failed JSON parsing.
