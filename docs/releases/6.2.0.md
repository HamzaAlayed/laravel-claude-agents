# Laravel Guild 6.2.0

## What’s new

Sensitive planned work now waits for an explicit, durable user decision. Each
stage may declare categories from its selected agent's harness profile, such as
`destructive migration`, `billing`, or `quality-gate reduction`.

- Pending lanes display `⏸`, stay out of `ready`, and reject `claim`.
- `guild approval list` shows each required decision.
- `guild approval grant` records the category, user-attributed provenance, and UTC time in
  kernel state before dispatch becomes possible.
- Claude Code prevents subagents from granting their own approval or directly
  rewriting `kernel.json`.

The complete workflow and command examples are in
[Runtime stage approvals](../approval-policy.md).

## Breaking changes

None. Existing delivery files load with empty approval fields, and
`approval_categories` defaults to an empty list for callers that have not yet
adopted the new field.

New plans created by the bundled orchestration commands always include the
field. Use an empty array only after deciding that none of the selected agent's
registered categories applies.

## Compatibility

Identity-aware runtime enforcement is Claude Code-specific. Gemini receives
the updated planning instructions and profile categories but cannot identify a
calling subagent in its hook payload. Codex Core does not ship Guild subagents.

An approval does not weaken an existing deny-rule. Production migrations,
destructive production SQL, and credential writes remain blocked by their
dedicated guards and require the separately privileged operator path named in
the block message.

This kernel gate covers planned deliveries. Direct single-specialist work
continues to rely on its prompt checkpoint, and the coordinator is instructed
not to select that fast path when a registered approval category applies.

## Verification

- Kernel units cover category validation, paused dispatch, failed pre-approval
  claims, durable provenance, idempotency, and CLI list/grant behavior.
- Integration tests prove pending Bash is denied, approved-but-unclaimed Bash
  remains denied, and an approved claimed stage proceeds.
- Guardrail cases cover self-approval, protected kernel state, unrelated lanes,
  read-only inspection, and malformed hook payloads.
