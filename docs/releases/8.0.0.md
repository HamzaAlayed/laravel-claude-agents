# Laravel Guild 8.0.0

## What’s new

Verification is now tied to the success criteria it is supposed to prove.
Every planned criterion has a stable ID, and every passing `VERIFIED` record
names exactly one of those IDs.

- `guild ready` returns the criteria that belong in the specialist brief.
- `guild criterion list` shows verified, waived, and pending criteria.
- Delivery boards render the same evidence matrix as `✓`, `~`, and `·`.
- A stage cannot finish until every criterion has evidence or an explicit user
  waiver.
- `guild criterion waive` persists the accepted gap, reason, user provenance,
  and UTC timestamp so it survives interruption and remains auditable.

The planning, reporting, and exception workflow is documented in
[Criterion-linked evidence](../criterion-evidence.md).

## Breaking changes

New stage reports use this exact record shape:

```text
VERIFIED: {"criterion":"valid-input-created","runner":"artisan-test","args":["--filter=CreateDonationTest"]} → 1 passed
```

The previous two-field shape with only `runner` and `args` is rejected. Direct
kernel integrations must add `criterion` to each record. The value must be one
of the stage's declared IDs, and the union of passing records must cover every
unwaived criterion.

New plans should supply a `criterion_ids` array parallel to
`success_criteria`. The CLI can derive positional IDs for compatibility, but
meaningful stable names are the supported orchestration contract.

## Migration

For an unfinished pre-v8 delivery:

1. Inspect its stage criteria with `guild criterion list`.
2. Add the corresponding `criterion` ID to every `VERIFIED` JSON object.
3. Add passing records until every criterion is covered.
4. If evidence truly cannot be produced, stop for a human decision. Only after
   the user accepts the exact gap should the main thread record a reasoned
   `guild criterion waive`.
5. Run `guild report` again and confirm the board shows no pending `·` marks.

Completed pre-v8 kernel state remains readable and complete. Its existing
successful evidence is not rewritten or falsely attributed to newly invented
IDs.

## Verification

- Kernel units cover stable ID validation, one-to-one mapping, full coverage,
  unknown-ID preflight, durable waivers, legacy-state loading, and board marks.
- CLI tests cover criterion listing and user-authorized waiver recording.
- Hook tests prove a main-thread waiver command is allowed while a specialist's
  self-waiver is denied.
- The full kernel, console, eval, guardrail, generated-target, manifest, shell,
  and frontend release gates pass before the tag is published.
