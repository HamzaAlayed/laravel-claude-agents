# Laravel Guild 9.6.0

Agent Security & Governance

## What’s new

Laravel Guild now defines who and what may authorize an agent action. Runtime
policy and an explicit current user decision are authoritative. Repository
text, approved memory, tool output, logs, issues, and external content remain
data rather than instructions and cannot grant capability or approval.

A cross-runtime pre-tool guard blocks direct secret reads and common
exfiltration shapes without copying the submitted path, command, URL, variable
name, or malformed payload into its diagnostic. A versioned registry exercises
13 attacks across all six STRIDE categories, and a source-bound posture receipt
seals the inspected policy, attack definitions, runtime instructions, guard
implementation, agent profiles, and hook manifests.

See [How do Laravel Guild agents stay inside their security boundary?](../agent-security-governance.md)
for the threat model, trust table, exact commands, limitations, and incident
runbook.

## Breaking changes

Direct reads of `.env*` except `.env.example`, credential and secret
directories, private-key files, process-environment enumeration, secret-shaped
shell output, credential-bearing fetch URLs, and common dynamic-data upload
commands now fail before execution on installed supported hooks.

Automation that intentionally used these agent tool surfaces must move secret
handling into a separately authorized service or operator-controlled process.
The harness provides no bypass flag because such a flag would become an
exfiltration path.

## Fixes

- Environment and credential files are protected from reads as well as writes
  across the declared Claude, Gemini, and Codex tool surfaces.
- Repository, memory, tool, log, issue, and external content cannot legitimately
  launder authority into a protected action.
- Unknown capabilities deny, read-only reviewers retain their mutation block,
  and security-boundary failures stop instead of triggering alternative
  encodings or retries.
- Posture receipts fail after source drift or receipt editing and exclude raw
  inputs that could themselves contain secrets.

## Compatibility

The policy engine and receipt tool use Python's standard library. Claude Code,
Cursor, Gemini, Codex, and classic project installs receive the new guard
through their existing hook mechanisms. No Laravel database migration,
application behavior change, external network call, or model spend is required.

The guard is pattern-based and is not an operating-system sandbox. Applications
with stronger isolation requirements should also use separate OS identities,
filesystem and network policy, short-lived credentials, secret scanning, and
service-side authorization.

## Verification

- Twenty-three focused tests cover the 13 registered attacks, all six STRIDE
  categories, safe developer commands, fail-closed malformed input, diagnostic
  redaction, zero-side-effect denials, receipt tampering, and source drift.
- The shell guardrail harness tests installed-hook behavior and the missing-
  Python fail-closed path.
- Claude, Gemini, and Codex generated targets are checked for exact source
  synchronization and sensitive-access hook wiring.
- The generated enforcement map publishes 20 controls.
- Immutable publication requires all 21 named hosted jobs for the exact v9.6.0
  commit and retains the release receipt.
