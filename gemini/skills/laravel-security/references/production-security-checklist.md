# Production security checklist

Use this checklist to collect release evidence and route remediation. Record the release SHA, environment, evidence link, owner, and status for each applicable ID. Leave a box unchecked until the control has verified pass evidence. Record the reason for any inapplicable control.

## Scope and rating

The reference versions are Laravel 13, PHP 8.4, PostgreSQL 17, React 19, Tailwind 4, and Vite 8. Verify against the deployed versions and lockfiles. No deployed topology, authentication flow, tenancy model, or sensitivity classification was supplied. Start with public users, authenticated users, privileged operators, and synthetic tenant pairs where isolation applies. Confirm which auth methods, jobs, uploads, storage services, edge layers, and AWS accounts/regions exist. Record the data classes and trust boundaries from browser to edge, API, tenant data, workers, object storage, and AWS.

Use CI, configuration review, read-only production evidence, and authorized staging tests with synthetic accounts and data. For each authorization regression, exercise the same operation and resource with one allowed actor and one denied actor. Check the response and the absence of unauthorized disclosure or state change. Capture effective runtime settings and delivered edge responses. Redact credentials and member data from evidence. Commands below are reference examples. Use the application's wrapper and installed-version options where applicable.

**Critical** covers plausible broad compromise, such as arbitrary execution or exposure of secrets or sensitive data across tenants. **High** covers material disclosure, privilege misuse, or service disruption. **Medium** covers narrower impact or failures requiring another condition. **Low** covers defense in depth with limited direct impact. Raise the rating for public exposure, weak prerequisites, privileged workflows, regulated data, or wider blast radius. Lower it when verified reachability, privileges, and data scope materially limit impact. **S** is up to half a day, **M** up to two days, and **L** more than two days or cross-team work, including retest.

ASVS entries identify directly relevant requirements. Top 10 entries identify risk categories. A mapping does not assess the whole requirement or establish compliance. **N/A** identifies a control with no direct mapping in that taxonomy. Choose a full ASVS level separately based on application risk. ## Authentication and sessions

- [ ] **AUTH-01 Set Secure on session cookies** — **Severity** High · **Effort** S · **Verify** Staging or read-only production, inspect effective Set-Cookie through the CDN after an authorized synthetic sign-in. - [ ] **AUTH-02 Set HttpOnly on session credentials** — **Severity** High · **Effort** S · **Verify** Staging or read-only production, inspect effective Set-Cookie on the login response. - [ ] **AUTH-03 Require MFA for privileged accounts** — **Severity** High · **Effort** M · **Verify** Staging, inspect policy for admins, support operators, and other accounts with elevated access, including break-glass accounts. - [ ] **AUTH-04 Rate-limit login attempts** — **Severity** High · **Effort** M · **Verify** Staging, compare the effective Laravel or IdP limiter against a bounded sequence of failed synthetic sign-ins from same and different test contexts. · **Pass** The configured account and abuse controls activate without exposing account existence or allowing trivial lockout of others. · **OWASP** ASVS v5.0.0-6.3.1 · Top 10 A07:2025.
- [ ] **AUTH-05 Enforce expiring single-use password resets** — **Severity** High · **Effort** M · **Verify** If password recovery is local, use staging mail capture and test one valid redemption, expiry with a test clock, and a duplicate redemption. - [ ] **AUTH-07 Terminate the session on logout** — **Severity** High · **Effort** M · **Verify** Staging, sign in, log out, then check access with the retained test cookie in an isolated browser context. - [ ] **AUTH-08 Enforce the post-password-change revocation policy** — **Severity** High · **Effort** M · **Verify** Staging, set up two browser sessions and representative API tokens for one synthetic account. - [ ] **AUTH-09 Match browser token storage to the authentication design** — **Severity** High · **Effort** M · **Verify** Staging, inventory browser storage, cookies, network requests, and token lifetimes. - [ ] **AUTH-10 Use calibrated password hashing** — **Severity** High · **Effort** M · **Verify** If passwords are stored locally, inspect effective Laravel hashing settings and use `password_get_info` with a synthetic hash. - [ ] **AUTH-11 Throttle API calls at the intended scope** — **Severity** High · **Effort** M · **Verify** Staging, exercise one approved synthetic API route at its documented user or tenant quota, including a second user. · **Pass** Calls above the limit receive the configured response and other users retain their expected capacity. · **OWASP** ASVS v5.0.0-2.4.1 · Top 10 A06:2025.

- [ ] **AUTH-13 Limit MFA challenge attempts** — **Severity** High · **Effort** M · **Verify** If code, push, or recovery challenges exist, inspect the policy and use a bounded series of synthetic challenge failures in staging. · **Pass** Attempts and push volume are limited and expiry and recovery behavior follow the design. · **OWASP** ASVS v5.0.0-6.6.3 for out-of-band codes, v5.0.0-6.6.4 for push · Top 10 A07:2025.

## Quick Wins

1. **OPS-01** — Inspect the effective document root and aliases first. Reduces exposure of the release tree. Confirm the serving paths point exclusively to intended public files.
2. **OPS-02** — Review private-path rules and test inert staging sentinels. Reduces credential and source disclosure. Confirm the origin and edge cannot deliver the sentinels.
3. **CI-01** — Check redacted secret scan coverage and run a synthetic blocker fixture. Reduces release of usable credentials. Confirm the gate fails and alerts the owner.
4. **WEB-01** — Inspect the built bundles and effective client environment prefix. Reduces credential exposure in shipped JS. Confirm the released artifact contains only public values.
5. **DATA-01** — Review actual PostgreSQL endpoint visibility and IPv4/IPv6 rules. Reduces externally reachable database exposure. Confirm only intended private paths can connect.
6. **OPS-03** — If private S3 exists, inspect effective Block Public Access and bucket policy. Reduces anonymous object exposure. Confirm approved service access and denial to anonymous consumers.
7. **APP-05** — Read the effective debug flag for the cached deployment. Reduces leakage of application internals. Confirm it is false and controlled staging errors remain generic.
8. **OPS-04** — Identify each TLS termination point and review its negotiated policy. Reduces insecure transport exposure. Confirm TLS 1.2+ and valid certificates on the intended path.
9. **AUTH-01** — Inspect Set-Cookie through the deployed edge after synthetic sign-in. Reduces plaintext exposure of sessions. Confirm Secure and the compatible scope on the session credential.
10. **CI-03** — Compare the deployed PHP and Laravel versions with official support tables. Reduces exposure to unpatched runtimes. Confirm the running versions are supported and within policy.
